# 水族分类与混养推荐设计

## 目标

让用户先按水体判断资料范围，再按生物类型浏览；详情页的混养区只给出少量适合优先考虑的对象，避免把风险清单误当成推荐清单。

## 当前问题

- 现有详情页展示所有启用的 pair rule，其中大多数是 `caution` 或 `conditional`，用户需要自己从风险描述中判断“能不能混”。
- 类型筛选只有鱼、虾、螺、水草，虾和螺各自作为一级入口，随着内容增长会显得过碎。
- 条目没有统一的水体字段，未来加入海水鱼、汽水鱼时只能继续堆标签，不能稳定筛选或生成入口。

## 采用方案

### 混养

在 `PairRule` 中增加 `visibility`：`recommended`、`caution`、`hidden`，默认旧规则迁移为 `hidden`。详情页只渲染 `recommended`，最多展示 3 个对象；若没有推荐则不渲染整个混养模块。推荐条目保留简短的适配理由和一个条件提示，名称链接到对应详情，不展示“不适合”对象。没有推荐时照料区域正常占用可用宽度。

这保留了编辑端未来继续记录风险判断的空间，也避免删除已有经验。当前 26 条目录只把证据较充分的同缸组合写成推荐：霓虹灯—火焰灯、霓虹灯—熊猫鼠、樱花虾—扁卷螺；其余规则在详情推荐区隐藏（公共只读 catalog 仍保留原规则），待后续有更完整条目和明确条件后再单独转为推荐。熊猫鼠与霓虹灯的推荐文案明确要求按 22–25°C 的交集规划，避免把温度重叠说得过宽。

### 分类

在 `DiscoveryTraits` 增加 `waterTypes`，枚举为 `freshwater`、`marine`、`brackish`。当前已有鱼、虾、螺和水草全部填写 `freshwater`；材料继续使用既有 `material.waterTypes`。这里表示日常观赏饲养水体，不覆盖每个繁殖阶段的盐度要求；黑金刚螺原有的繁殖备注保留。

前台保留 URL 兼容的 `type=fish|shrimp|snail|plant`，新增 `water` 参数和“水体”筛选。展示层将动物类型归并为：鱼类、水草、虾螺；虾螺覆盖虾和螺，旧的虾/螺 URL 仍可直接访问。水体筛选只显示当前目录中存在的环境，未来加入海水或汽水条目后自动出现对应选项，不展示空的伪入口。

首页和水族库一级入口改为“全部、鱼类、水草、虾螺”，水体作为紧邻的筛选维度；鱼类详情仍显示现有的科属/品种分类，避免把“灯科鱼”等爱好者分类和水体混为一层。

## 不做

- 不把海水、汽水空分类做成有 0 条结果的主导航。
- 不删除或公开当前的风险规则；只改变前台展示策略。
- 不对现有条目编造海水/汽水属性，不扩充新物种内容。
- 不引入后台/CMS或来源许可录入流程。

## 验收

- 中英文首页和水族库显示鱼类、水草、虾螺三个生物入口；虾/螺旧 URL 仍可用。
- 当前目录的水体筛选至少显示淡水，筛选结果覆盖现有 18 个水族条目且 URL 可复制返回。
- 详情页最多显示 3 个“适合混养”推荐；风险/谨慎规则不再出现在公开混养区；无推荐时模块隐藏。
- 中英文、桌面和 390px 页面无横向溢出，详情返回筛选条件保持。
- 旧的 26 条实体、照片、鱼类喂食信息保持不变；内容测试、typecheck、build 和生产 smoke 通过。
