# V0 acceptance / V0 验收清单

版本：0.4；2026-11-05。范围以[开工基线](开工基线与任务看板.md)为准。本文定义完整 V0 的通过条件；内核检查不等于游戏通过。

## 状态与门槛

- **逻辑已检**：控制台实际运行的自动检查，不包含 Unity。
- **配置已检**：CSV 引用、数量、预算、命名与首批en/zh-CN静态检查通过；多语言改造须另记新验证。
- **待集成**：仍缺系统、资产或连接。
- **待 Unity**：有源码，尚无编辑器编译、Play 或构建实测。

全部 P0 必须在真实构建通过；P1 未通过项需明确影响和后续安排。当前尚未达到完整 V0 门槛。真实游戏验收须记录构建版本、机器、复现步骤、预期、实际和证据。

## 推荐路线复现

1. 新建60cm缸，确认1500金币，按 `data/route.csv` 买必需品，共1110。
2. 确认前撤回退款；验证可选沉木不会挤占首批鱼虾资金。
3. 注水、启动过滤和灯，完成无鱼氮源挑战；提前入鱼须说明原因并拒绝。
4. 买8尾火焰灯120、6只虾180，余90；完成适应观察、基础投喂与换水。
5. 只领一次450奖励，买8尾霓虹灯260，余额280。
6. 推近观察、开关灯和投喂；暂停/日历倍率不改变真实反应速度。
7. 遍历注册表内本次发行locale切换，保存退出读取；核对完整状态、偏好、英文回退和后续行为连续性。开发QA另测qps-ploc/draft，不能将planned算通过。
8. 在副本注入坏档、奖励事件重放、重试重复请求；核对无丢失或刷取。

命令与实际结果见[实施状态与验证记录](实施状态与验证记录.md)。`--strict-release` 当前应因待核验/未实现契约失败，不得删除标记假装完成。
