# 多语言观赏鱼物种决策数据库

> 设计文档 / PRD + MVP 开工规格
> 日期：2026-11-05
> 状态：已审核，进入分阶段实施
> 项目代号：FishAtlas（暂定名）

## 1. 意图与产品判断

本项目建设一个多语言观赏鱼整理网站，围绕“我能不能养、怎么养、能不能混养、买什么设备”组织信息。它首先服务于站长和同好日常查阅、整理与分享，搜索引擎是自然增长入口，联盟购买链接只是后续可选的变现方式。

P0 先做英语和简体中文，每种语言 50 个高需求品种；第三语言只预留路由和数据结构，待内容资源确认后再加入。每个品种页都要回答基础饲养参数、难度和混养风险，维护者能够从录入到发布再到纠错完成闭环。

工作区已有一个独立的 Unity 观赏鱼布景游戏规格包。本项目作为网站产品单独建模，不复用游戏的购买、负荷或行为参数；如果后续需要共享物种资料，必须通过明确的数据导出契约完成。

## 2. 目标、非目标与反目标

### 2.1 目标

- 新手可按缸体尺寸、水温、难度、水层快速缩小候选范围。
- 爱好者可查学名、别名、体长、水质参数、食性、群养数量、最小缸体、攻击性和品系差异。
- 混养决策有条件、风险和理由，能解释“为什么谨慎”。
- 非英语用户获得原生撰写的本地语言内容，页面语言与搜索结果稳定对应。
- 内容状态、更新时间和编辑记录可追溯。
- 内容维护者无需开发即可新增、审核、更新、下线品种。
- 核心品种页可被索引，且能从搜索进入筛选和养鱼决策路径。

### 2.2 首发不做

- 不复制或翻译 Seriously Fish、FishBase 等站点的整页内容。
- 不一次性覆盖全品种、全语种、所有水草和疾病内容。
- 不把 AI 生成图片作为未标注的物种主图。
- 不首发建设社区、评论、交易市场、独立水草库或公开 API。
- 不以月访问百万作为首发成功标准。

### 2.3 反目标

以下结果即使页面数量增长，也视为项目失败：

- 内容长期无人维护，页面参数互相矛盾或明显过期。
- 机翻内容被当作本地语言正文发布。
- 页面给出没有解释的“可混养/不可混养”结论，导致用户误判风险。
- 为了补齐字段而把未经确认的内容写成确定结论。
- 内容生产速度超过审核能力，形成大量过期或互相矛盾的条目。

## 3. 约束与已定产品规则

### 3.1 内容可信度

1. 网站定位是爱好者整理和分享，不建立学术论文式的逐字段引用系统。
2. 内容以原创整理、个人观察和公开资料交叉了解为主；不整页复制其他网站，不把不确定信息写成绝对结论。
3. 每个条目保留编辑人、最近更新时间、内容状态和一段简短的“内容说明”，例如“综合多份资料整理，参数存在地区差异”。
4. 暂时无法确认的字段留空，显示“数据不足”或“待确认”，由编辑决定是否进入公开页面。
5. 图片只记录展示状态和是否为占位图，不建立额外的资料登记系统。

### 3.2 图片规则

- 优先使用自己拍摄或明确可以使用的图片。
- 图片无法确认时不作为正式物种照片展示。
- AI 图片只能作为明确标注的占位或装饰，不作为物种真实照片。
- 没有可靠图片时显示“暂无照片”，不使用来路不明的图片补位。

### 3.3 多语言规则

- P0 只发布英语和简体中文；第三语言先预留路由和字段，等内容资源稳定后再加入。
- 每个语言版本有独立的标题、摘要、常用名、正文和 SEO 元数据。
- 多语言正文由对应语言的编辑原生撰写，不把英文页作为自动翻译源。
- 页面必须显示内容状态：已发布、部分翻译、待确认或数据不足。
- URL 使用稳定语言前缀，例如 `/zh-cn/species/neon-tetra`；语言切换保持物种稳定 ID。

## 4. 构建方式与取舍

### 方案 A：静态内容仓库 + 定时构建

物种条目以 Markdown/JSON 存储，提交后构建 SSR/静态页面。优点是成本低、性能好、版本记录天然清晰；缺点是非技术内容编辑需要 Git 或额外编辑工具，内容和图片审核容易被拆散。

### 方案 B：关系型内容库 + 轻量 CMS + SSR（选定）

将物种、语言版本、内容状态、图片信息和审核记录拆成可查询实体；前台使用 SSR/静态缓存，后台提供表单和审核队列。优点是适合多语言状态和纠错流，后续可扩展对比、收藏和联盟统计；代价是需要设计权限、发布快照和数据校验。

### 方案 C：先做大型百科/社区平台

同时加入评论、问答、交易和全品种扩展。它能覆盖更多场景，但会把内容审核、用户安全和商业模块提前引入，超出首发验证目标。

### 选定结论

采用方案 B。P0 先实现物种查询、筛选、详情、内容/图片审核和发布；对比、收藏、纠错用户流和联盟统计作为 P1 扩展。前台页面采用 SSR 或静态生成加 CDN，后台发布生成带版本号的可回滚内容快照。

## 5. 用户与核心任务

### 新手：判断“我的缸能养什么”

1. 进入首页，输入缸体尺寸或选择预设尺寸。
2. 选择温度、难度、水层和水质范围。
3. 查看候选列表，按“适配度、难度或体长”排序。
4. 打开详情页，确认最小缸体、群养数量、风险提示和设备建议。

### 进阶爱好者：查一个品种并评估混养

1. 用常用名、学名或别名搜索。
2. 在详情页查看识别信息和参数区间。
3. 查看“适合混养对象”“谨慎对象”和“高风险对象”，每条建议有原因和适用条件。
4. 保存或复制品种清单（P1）。

### 非英语用户：阅读本地化内容

1. 通过本地语言搜索结果进入对应语言 URL。
2. 页面显示本地常用名、原生摘要和状态标签。
3. 语言切换后保留当前物种、筛选条件和滚动位置（条件允许时）。

### 内容维护者：完成一个条目的发布闭环

1. 创建物种草稿和稳定 ID。
2. 录入识别字段、原创内容、内容说明和更新时间。
3. 上传图片并标记正式图片、占位图或暂无照片。
4. 为每种语言创建内容，提交编辑审核。
5. 通过内容、图片、语言和 SEO 闸门后发布。
6. 处理用户纠错，形成新版本并保留历史记录。

## 6. 信息架构与页面规格

### 6.1 P0 页面

| 页面 | URL 形态 | 主要内容 | 验收重点 |
|---|---|---|---|
| 首页 | `/{lang}` | 搜索框、筛选入口、热门品种、决策入口、说明链接 | 3 秒内理解产品用途；移动端可操作 |
| 搜索/筛选结果 | `/{lang}/species` + 查询参数 | 关键词、筛选芯片、结果卡片、排序、空状态 | 组合筛选可刷新 URL；结果可解释 |
| 物种详情 | `/{lang}/species/{slug}` | 识别、参数、难度、混养建议、设备、图片和更新时间 | 关键字段完整率 ≥95%；内容状态清晰 |
| 品种/分类落地页 | `/{lang}/guides/{topic}` | 例如小缸鱼、群游鱼、低难度鱼 | 与筛选结果有内链；可被索引 |
| 纠错入口 | `/{lang}/corrections` | 物种、字段、问题描述、联系方式（可选） | 提交后有编号和状态提示 |
| 说明页集合 | `/{lang}/legal/*` | 图片说明、隐私/Cookie、内容说明 | 全站可达；正文有版本日期 |
| 鱼缸计算器（P1） | `/{lang}/calculator` | 缸体输入、鱼种与数量、分项检查、风险说明 | 结果可解释；缺数据时显示数据不足 |

### 6.2 物种详情页结构

1. **首屏摘要**：本地常用名、学名、难度、推荐缸体、适合水层、主图或“暂无照片”。
2. **快速参数**：成体体长、温度、pH、硬度、食性、群养数量、攻击性。
3. **饲养判断**：原创描述、适合人群、常见失败原因、设备最低建议。
4. **混养判断**：可混养、谨慎混养、风险对象；每条包含条件、理由和风险等级。
5. **识别与分类**：分类、异名、分布、品系/变种关系。
6. **内容说明与版本**：内容状态、更新时间和编辑时间线。
7. **设备建议**：给出基础缸体、过滤、加热和灯光建议；购买链接留到后续评估。

## 7. 功能需求与验收

### 7.1 P0 必须上线

| 编号 | 需求 | 验收标准 |
|---|---|---|
| P0-01 | 物种条目 | 英语和简体中文各 50 个核心品种；关键字段完整率 ≥95% |
| P0-02 | 字段状态 | 每个关键字段有 `verified / needs_review / insufficient_data / unpublished` 状态；未发布字段不进入前台 |
| P0-03 | 搜索 | 支持本地常用名、学名、别名；前缀和包含匹配；结果显示物种状态和语言 |
| P0-04 | 筛选 | 难度、水温、pH、缸体、水层至少支持范围筛选；筛选条件写入 URL；移动端可用 |
| P0-05 | 详情页 | 学名、异名、分类、分布、成体体长、温度、pH、硬度、水层、食性、性情/攻击性、群养数量、最小缸体、难度、原创描述和混养建议均有展示位 |
| P0-06 | 图片管理 | 图片标记正式图片、占位图或暂无照片；占位图不能伪装成真实物种照片 |
| P0-07 | 内容与版本 | 可查看编辑版本、更新时间和内容状态；支持回滚最近一次发布版本 |
| P0-08 | CMS | 非技术编辑可完成新增条目、录入内容说明、传图、提交审核、发布和下线 |
| P0-09 | SEO | SSR/静态页、canonical、sitemap、hreflang、JSON-LD、标题/摘要模板、相关内链 |
| P0-10 | 说明与隐私 | 图片说明、隐私/Cookie、纠错入口可访问 |
| P0-11 | 性能与可访问性 | 移动端核心页面 LCP < 2.5s；图片 WebP/AVIF、懒加载；键盘可导航、对比度合格、图片有 alt |

P0 关键字段固定为：常用名、学名、成体体长、温度范围、pH 范围、硬度范围、水层、食性、性情/攻击性、群养下限、最小缸体、难度、原创描述和混养摘要。关键字段完整率的分母就是这 14 项；字段状态为 `insufficient_data` 时计入已处理，但页面必须显示“数据不足”。

筛选采用“区间有交集即可命中”：用户输入的温度、pH、GH 区间只要和物种区间有重叠就保留；用户输入最小缸体时按物种最小缸体小于等于用户值命中；缺失字段不算命中，并提供“数据不足”状态，不自动排除整个物种。

### 7.2 P1（上线后 3–6 个月）

- 混养兼容矩阵：规则 + 风险原因 + 置信度 + 适用前提。
- **鱼缸方案计算器**：输入缸体尺寸或可用水量，添加物种和数量，输出空间、群养、水温/水质、水层和混养风险的分项判断。
- 2–4 个品种对比。
- 收藏和“我的缸可养清单”。
- 用户纠错的后台处理状态和通知。
- 按语言接入当地水族电商或设备品牌并统计点击/转化（可选）。
- 设备建议字段扩展到缸体、过滤、加热、灯光最低建议。
- 品系/变种独立页，明确人工品系与野生种关系。

计算器的 P1 验收标准：

1. 支持长/宽/高（cm）和可用水量手动覆盖；显示毛体积与估算可用体积的区别。
2. 同一物种可设置数量，低于群养下限时单独提示；不自动把低于下限的方案判为安全。
3. 对每个物种分别检查最小缸体、成体体长和群养条件；跨物种检查温度、pH/GH（如有数据）、水层和兼容规则。
4. 结果分为“可尝试 / 谨慎 / 不建议 / 数据不足”，每个结论显示触发它的具体条件。
5. 任一关键参数缺失时显示部分计算或数据不足，不把缺失当作通过；结果页注明“估算仅供参考”。
6. 算法规则带版本号，后续调整规则不会改变历史方案的记录。

### 7.3 P2（验证后）

社区问答、评论、繁殖/疾病/水草关联库、API/数据导出、广告保底和更多语言。

## 8. 数据模型

以下模型是 P0 的最小契约。字段可扩展，但稳定 ID 和版本关系必须保持兼容。

### 8.1 `species`

| 字段 | 类型 | 规则 |
|---|---|---|
| `id` | string | 永久稳定 ID，建议 `neon-tetra`；不因翻译改变 |
| `scientific_name` | string | 学名；录入人确认后可发布 |
| `taxonomy` | JSON | 界/门/纲/目/科/属/种；保留编辑备注 |
| `distribution` | text/JSON | 分布范围与编辑备注；不把观赏贸易地当自然分布 |
| `aliases` | string[] | 搜索别名，标注语言和备注 |
| `status` | enum | `draft / review / published / archived` |
| `content_confidence` | enum | `high / medium / low`；由编辑依据字段状态汇总 |
| `created_at / updated_at` | datetime | 审计字段 |

### 8.2 `species_localizations`

| 字段 | 类型 | 规则 |
|---|---|---|
| `species_id` + `locale` | composite key | 每个语言版本唯一 |
| `common_name` | string | 本地常用名；记录编辑备注 |
| `slug` | string | 语言独立、稳定、可读 |
| `title / summary / body` | text | 原生撰写；不得由系统自动翻译后直接发布 |
| `translation_status` | enum | `missing / draft / editorial_review / published / needs_update` |
| `seo_title / seo_description` | string | 本地语言 SEO 文案 |
| `last_reviewed_at` | datetime | 语言内容最近审核时间 |

### 8.3 `care_profiles`

每个物种可拥有多个带版本的参数集合，支持品系差异和后续调整。P0 字段包括：

`adult_length_cm`、`temperature_min_c`、`temperature_max_c`、`ph_min`、`ph_max`、`gh_min`、`gh_max`、`water_layer`、`diet`、`temperament`、`aggression_level`、`school_min`、`school_recommended`、`minimum_tank_l`、`difficulty`、`equipment_baseline`。

每个字段同时保存 `value`、`unit`、`status`、`last_reviewed_at` 和可选 `editor_note`。范围冲突时显示“资料存在差异”，由编辑写出适用条件；系统不得自动取平均值。

为 P1 鱼缸计算器预留以下字段，P0 可以先录入但不要求全部启用：

`calculator_enabled`、`calculator_min_tank_l`、`calculator_group_min`、`calculator_space_increment_l`、`calculator_bioload_index`、`calculator_activity_level`、`calculator_zone_weights`、`calculator_temperature_tolerance_c`、`calculator_ph_tolerance`、`calculator_gh_tolerance`、`calculator_data_status`。

这些字段是站内估算参数，不宣称现实世界的统一科学公式。`calculator_space_increment_l` 和 `calculator_bioload_index` 只在算法版本中使用，并在后台标明“估算调参”；缺失时返回数据不足。

### 8.4 `compatibility_rules`

| 字段 | 说明 |
|---|---|
| `id` | 稳定规则 ID |
| `subject_species_id / object_species_id` | 规则两端；支持物种或类别引用 |
| `decision` | `compatible / caution / avoid / unknown` |
| `risk_level` | `low / medium / high` |
| `conditions` | 温度、体型、缸体、群体、食性等前提 |
| `reason` | 原创解释，面向用户 |
| `editor_note` | 适用条件、个人观察或风险解释 |
| `status` | `draft / review / published / retired` |
| `reviewed_at` | 最近复核时间 |

P0 允许详情页展示人工编写的“常见对象”卡片；矩阵查询和批量兼容计算留在 P1。

### 8.5 `content_notes`

| 字段 | 说明 |
|---|---|
| `id` | 内容备注 ID |
| `entity_type / entity_id` | 关联物种、语言、参数或规则 |
| `note_type` | `editor_note / personal_observation / uncertainty / update_note` |
| `text` | 面向编辑或用户的简短说明，不复制外部正文 |
| `author_id` | 记录人 |
| `created_at` | 记录时间 |
| `visibility` | `internal / public` |

### 8.6 `media_assets`

记录 `id`、`species_id`、文件 URL、缩略图、alt 文本、图片状态、AI/占位标记、上传人和时间。前台只加载正式图片；无法确认时使用暂无照片。

### 8.7 `content_versions` 与 `corrections`

`content_versions` 保存发布快照、变更摘要、编辑人、审核人、发布时间和回滚目标；`corrections` 保存用户提交的页面、字段、问题描述、联系方式、状态、处理备注和关联版本。用户联系信息最小化保存并设置保留周期。

### 8.8 `tank_profiles` 与 `tank_plan_items`（P1 预留）

`tank_profiles` 保存用户在计算器中输入的方案：

| 字段 | 说明 |
|---|---|
| `id` | 方案 ID；P1 可只存在于 URL 或浏览器本地 |
| `length_cm / width_cm / height_cm` | 缸体尺寸；允许为空但至少要有可用水量 |
| `gross_volume_l` | 按尺寸计算的毛体积 |
| `usable_volume_l` | 用户手动输入或按水位/造景估算的可用水量 |
| `water_temperature_c` | 方案目标温度 |
| `ph / gh` | 可选水质输入 |
| `water_layer_preferences` | 可选的水层偏好 |
| `algorithm_version` | 计算规则版本 |

`tank_plan_items` 保存方案中的物种行：`tank_profile_id`、`species_id`、`quantity`、`variant_id`（预留）、`notes`。同一物种默认合并数量；如需比较不同品系，可使用不同 `variant_id`。

P1 首版可以只把方案编码进 URL 或保存在浏览器本地，暂不要求账号、云端保存或公开分享。若后续需要跨设备保存，再增加用户账户和服务端方案表。

## 9. 内容状态与发布闸门

### 9.1 字段状态

- `verified`：编辑确认可展示，最近复查时间已记录。
- `needs_review`：需要补充观察、核对或处理资料差异。
- `insufficient_data`：当前没有足够把握，前台显示数据不足。
- `unpublished`：内部草稿或图片使用状态未确认，前台不可见。

### 9.2 条目发布门槛

条目只有同时满足以下条件才能进入 `published`：

1. 必填识别字段齐全，关键参数字段完整率达到 95% 以上。
2. 每个关键字段都有明确状态；`needs_review` 和 `insufficient_data` 在页面上有相应提示。
3. 每种语言都有原生正文、标题、摘要和 SEO 元数据，或明确标记为部分翻译且产品负责人批准上线范围。
4. 至少一张使用状态已确认的主图，或页面明确使用“暂无照片”状态。
5. 混养建议中的每条结论都有理由、适用条件和审核人。
6. SEO、结构化数据、canonical、hreflang、内链和移动端验收通过。

### 9.3 角色与权限

| 角色 | 权限 |
|---|---|
| 内容编辑 | 创建和修改草稿、录入正文和内容说明 |
| 语言编辑 | 修改对应语言、确认本地命名和 SEO 文案 |
| 图片审核员 | 确认图片状态、是否为占位图和 alt 文本 |
| 饲养审核员 | 审核参数、风险和混养建议 |
| 发布管理员 | 合并审核结果、发布、回滚、下线 |
| 只读分析员 | 查看版本、指标和内容备注，不改内容 |

同一人可以完成大部分编辑工作；发布时保留最后审核人和操作日志即可。

## 10. 后台工作流

```text
选品 → 建立稳定 ID → 识别字段录入 → 内容整理
  → 原创内容撰写 → 语言编辑 → 图片状态确认
  → 参数/混养审核 → SEO 与可访问性检查
  → 发布快照 → 索引监测 → 纠错/过期复核
```

每个状态迁移记录操作者、时间、变更摘要和阻塞原因。发布失败时给出字段级错误，例如“pH 范围待确认”或“zh-CN 正文未完成”，而不是只显示“校验失败”。

## 11. SEO、性能和工程边界

### 11.1 前台

- 采用支持 SSR/静态生成的 Web 框架；物种详情和落地页优先静态生成并由 CDN 缓存。
- 搜索结果和筛选页允许动态请求，但 canonical 指向可索引的规范 URL。
- 每个物种页生成 `Article`/`Thing` 或适用的 `Product` 之外的语义结构化数据；不得把联盟商品伪装成物种商品。
- `hreflang` 只指向实际存在且可发布的对应语言页。
- 图片生成 WebP/AVIF 多尺寸，首屏主图优先加载，其余懒加载。

### 11.2 后台与数据

- 关系型数据库保存规范化实体和版本；全文搜索索引物种名、别名和语言正文。
- 发布过程生成不可变内容快照；前台只读已发布快照。
- 备份至少包含数据库、媒体元数据、发布快照和操作日志；恢复需做抽样演练。
- 语言、字段和品种通过配置扩展，避免新增语种时修改业务表结构。

### 11.3 安全与隐私

- 后台使用最小权限和二次验证（若平台支持）。
- 纠错表单默认不要求用户账号；邮箱为可选字段。
- Cookie、分析和联盟追踪在当地法规要求下获取同意并记录版本。

## 14. 指标、事件与报告口径

### 上线前质量指标

- 关键字段完整率：已发布条目中有值且状态为 `verified` 或明确 `insufficient_data` 的关键字段数 / 关键字段总数，目标 ≥95%。
- 内容审核覆盖率：已发布条目中有审核人和最近更新时间的条目 / 已发布条目，目标 100%。
- 图片状态覆盖率：主图已标记正式图片、占位图或暂无照片的条目 / 已发布条目，目标 100%。
- 语言发布率：每个首发语言完成且通过审核的条目 / 该语言计划条目，目标 100%。

### 上线后业务指标

- 核心品种页收录率 ≥80%（上线 0–3 个月）。
- 每语种至少 30 个品种有稳定搜索曝光（3–6 个月）。
- 若接入联盟，统计详情页点击率、点击到转化率和每语种收益。
- 搜索无结果率、筛选后零结果率、纠错提交量和纠错关闭时长。
- 若接入联盟，观察收益是否覆盖内容、托管和审核成本。

分析事件至少包含 `search_submitted`、`filter_applied`、`species_viewed`、`notes_expanded`、`affiliate_clicked`、`correction_submitted` 和 `language_switched`，事件中不得包含不必要的个人信息。

## 15. 阶段目标与发布闸门

### 0–3 个月

完成英语和简体中文、每种语言 50 个品种、内容审核和图片状态流程；核心品种页收录率达到 80%。

### 3–6 个月

观察核心长尾词曝光、筛选使用率和详情页停留；根据使用情况扩展对比、收藏、兼容矩阵和可选联盟入口。

### 6–12 个月

评估扩展到每语种 80–100 个品种，再决定是否加入第三语言；月自然访问保守目标为 1–3 万。根据维护成本收缩语种或品种范围。

### 首发阻断条件

任意一项成立则延期发布相关条目或整体上线：

- 已发布条目没有审核人或更新时间。
- 图片使用状态缺失，或存在未标注 AI 主图。
- 任一首发语言只有机翻正文，未完成原生编辑审核。
- CMS 无法完成新增、录入内容说明、传图、发布、纠错闭环。
- hreflang、canonical、sitemap 或隐私说明存在高优先级错误。
- 移动端核心页面 LCP ≥2.5s 且没有明确修复计划。

## 16. 待冻结事项与设计调用

以下事项需要在开工前冻结；已根据本次讨论写入默认做法：

1. **首发范围**：P0 只做淡水观赏鱼；首发英语和简体中文，主要面向中国大陆和英语市场。
2. **多语言发布**：每个语言版本可以独立发布；未完成语言不进入 sitemap/hreflang；`insufficient_data` 可计入已处理字段，但页面必须显示状态。
3. **首批 50 个品种**：默认按搜索需求、新手覆盖和混养覆盖打分；每语种可以共享物种 ID，但本地优先级和常用名独立维护。
4. **技术栈**：默认采用支持 SSR/静态生成、关系型数据库和对象存储的成熟 Web 栈；具体框架由工程负责人根据现有部署能力决定。
5. **联盟链接**：不属于 P0；只有确认有同好购买需求后再接入。
6. **内容复核周期**：默认核心参数每 90 天复查一次，外链失效按每周人工检查处理。
