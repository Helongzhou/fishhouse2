# 03 UI/UX 与素材生产方案

日期：2026-11-06。范围：设计说明与实施交付约束。本文没有批准产品实施、安装技能、生产图片或修改网站；文中的尺寸、颜色、首发素材规模与模板均为设计负责人建议，须纳入总方案评审。

## 1. 设计判断与现状依据

建议主案为“自然图鉴 + 造景工作台”：用真实造景照片建立水族体验，以清楚的物种照片帮助识别，用可操作的缸体画布承接开缸任务。界面靠比例、留白、排版和图像形成层级；不继续用一排排标签、介绍段落和装饰框解释页面用途。

本次只读核对了 `styles.css`、`app.js`、`README.md`、现有升级/QA 报告，以及 `qa-artifacts/cache-fix/database-1440-zh-CN.png` 和 `ember-detail-390-zh-CN.png`。当前为 10 个示例动物的中英静态站，正式物种照片未交付；已有淡绿背景、深绿按钮、金色分类标签、参数卡片和触屏可展开内容。现有信息层级比旧版清楚，但照片缺失令列表成为重复的数据表，移动详情仍较长。现有 QA 通过的是该静态范围，不证明新首页、设计器或后台已经可用，也不证明视觉质量达标。

美术改进必须同时覆盖：真实素材、页面构图、字体与密度、控件细节、工作流。仅换色或安装设计技能不能解决这些问题。

### 两种可比较的方向

| 方向 | 页面气质与构图 | 优点 | 代价与风险 |
| --- | --- | --- | --- |
| A：自然图鉴 + 造景工作台（推荐） | 暖白底、深墨绿文字与操作、真实造景大图；图鉴采用整齐照片网格；设计器采用浅色工具面板围绕画布 | 与动物、植物、石木的真实质感相配，资料易读，工作台可高效操作，中英扩展自然 | 需要合格的照片和场景素材；不能拿 AI 鱼图填补缺口 |
| B：水族摄影展厅 | 深色底、低饱和界面、大幅照片、较少首屏内容，设计器也偏深色 | 氛围强，适合摄影与高质量造景展示 | 对摄影质量更苛刻，数值与后台表单可读性成本更高，低质量素材和透明边缘更显眼，手机浏览密度低 |

推荐 A 作为全站基础。B 可在后续独立的作品展示页验证，不把两套主题混用在首版。两案均不能用“高级感”“更自然”作为验收结论，须检查真实内容与完整交互。尚未将任何方向记为用户已选。

## 2. 共同设计规则

### 视觉规范建议

| 项目 | 建议基线 | 使用约束 |
| --- | --- | --- |
| 页面底色 | 暖白 `#F7F8F4`；面板 `#FFFFFF` | 大块背景不反复套卡片；内容区用间距和分隔线组织 |
| 主文字 / 次文字 | `#18302D` / `#596B63` | 次文字也必须通过实际对比度检测，不能靠浅灰降低存在感 |
| 操作主色 | `#174E43`，白字 | 用于主要提交、当前选择与必要链接；不把所有标题刷绿 |
| 强调色 | `#C6A35C` | 只作少量品牌点缀，避免金底小标签成为每张卡的视觉中心 |
| 边线 / 状态 | `#D8E0D7`；错误、提醒、成功独立语义色 | 状态同时有文字/符号；颜色建议必须经过 WCAG 对比度检查后才冻结 |
| 字体 | 系统中文无衬线 + 系统拉丁无衬线；学名斜体 | 不为中英混排强行加大字距；数值用等宽数字；中文有可靠本地回退 |
| 正文与标题 | 正文 16px、行高 1.6；UI 14–16px；辅助信息 13px；H1 桌面 40–48px / 手机 30–34px；H2 24–28px | 不靠缩小字体塞信息。后台密集表格最低建议 14px；不将关键参数藏在辅助字号 |
| 栅格与间距 | 桌面内容上限 1280–1320px，边距 32–48px；手机边距 16px；8px 间距基线，主要区段间距 40–64px | 参考断点 768/1024/1280px，以实际内容溢出决定，不按设备名称硬切 |
| 形状 | 普通面板圆角 8px、媒体 8–12px、弹窗 12px | 不做连续胶囊标签；阴影只用于浮层和抬起的选中对象 |
| 控件 | 主要触屏目标至少 44×44px；表单通常高 44px；边框清楚 | 图标需统一来源与笔画；只在含义明确的常用操作省略可见文案，并提供可访问名称 |
| 动效 | 120–180ms 的状态反馈；画布动效可关闭 | 支持 `prefers-reduced-motion`；首屏不自动播放鱼群或漂浮装饰 |

这些是实施起点，不是未经渲染就可签收的品牌规范。必须以中英真实内容、真实照片、真实手机截图调整。

### 信息与文案

- 每页一个明确主任务；标题下不默认加英文眉题、卖点短句、状态标签和说明段。首页可保留一句必要的承诺；操作解释只在用户需要做决定时出现。
- 数据标签仅用来解释数值，如“成体体长”“最小缸体”；不重复物种已显示的类型或多次展示同一体长。已选筛选条件属于操作状态，可保留并可删除；不是装饰标签。
- 未知值呈现“待补充”并关联具体字段；不以 0、空字符串或默认安全值冒充已知。不可用一个总“已核实”徽章覆盖不同来源与质量的数据。
- 首发导航建议“水族库 / 开缸设计”，品牌返回首页。后台为独立管理入口；没有实现的功能不以可点击正式入口冒充可用。

### 多语种与可访问性通则

- 简体中文与英语独立词条；分类、物种、参数枚举用稳定 ID，对象和方案名称不因切语丢失。切语保留筛选、缸体、选中对象、数量与未保存编辑，不重新创建方案。
- 英文按钮与长学名允许自然换行；不得仅以中文短文本定宽。数字与单位格式统一；首版建议尺寸 cm、体积 L、温度 °C，单位转换另列范围，不能显示一个单位却用另一个单位计算。
- 首批内容中英齐全；之后各语言独立发布。某语言未完成首次发布时不公开该详情、不进入 sitemap/hreflang，也不按段英语兜底；新修订未完成时保留该语言上次有效版本。缺译与依赖冲突集中在后台定位。
- 语义化标题、导航、表单标签、fieldset、错误关联；所有流程可键盘完成，焦点清楚，关闭弹窗返回触发位置。普通文字对比度至少 4.5:1，大字和必要 UI 图形至少 3:1，200% 缩放不丢功能；320 CSS px 不产生整页横向滚动（画布可在明确容器内缩放平移）。
- 不只靠 hover、拖拽、颜色或图像承载信息；图片有适当替代文本，装饰图空 alt。搜索结果计数、保存与验证状态使用克制的 live region，不在拖动每一帧朗读。

## 3. 五个关键页面规格

### 3.1 首页：让用户看懂水族体验并开始一项任务

**桌面文字线框**：`导航` → `左：一个标题 + 搜索 + 浏览水族库；右：真实造景主图 + 开始设计入口` → `两个可选开缸模板的真实/经审核示意预览` → `少量精选物种照片网格` → `简洁页脚`。标题与画面比例约 4:6；主图建议 16:10。模板采用图像和名称直接表达差异，无需三四枚“专业/生态/新手”等描述标签。

**手机**：标题和搜索在前，主图紧接；主按钮进入设计，次入口浏览库；模板横向内容不强制用户滑动才能发现第二张，建议单列两张。首屏不放统计数字和大型宣言占满视口。搜索必须支持中文名、英文名、学名和别名；选中结果去详情，提交文本去保留查询的库页。

**状态**：精选无数据就隐藏该模块；全站数据失败保留导航和重试入口，搜索显示失败原因。主图加载保持比例，可用模糊低清预览但避免闪烁。主图加载失败或缺失时使用干净的品牌色块与现有图文结构，并移除摄影作品式的视觉承诺；不拿 AI 缸景暗示实际模板效果。R1不展示未交付设计器入口；R2上线后模板未达可用门槛只显示可用模板，没有可用模板时允许从空缸新建。

**验收**：真人造景照片是焦点，文字可读且不压住主体；首屏能找到搜索和开始设计。照片对应的布局模板若可打开，打开后对象与构图应可解释地对应；摄影参考与可编辑模板分清，不让用户误以为照片能一键完整还原。

### 3.2 水族库：快速识别、筛选并比较条件

**桌面文字线框**：`标题 + 搜索 + 结果数/排序` → `类型切换` → `左 220–240px 筛选；右照片卡片网格`。宽桌面三列，普通桌面两列；以照片主体可识别和关键文字舒适为前提。照片建议 4:3；卡片依次为名称、学名、精简条件。默认展示成体体长/水温/最小缸体/群体四项，类型不同换用有意义的参数，不给植物和石木套鱼类的“群体”字段。

**类别变化**：水族库顶层采用全部/鱼类/虾类/螺类/水草；材料在设计器素材目录及独立材料页面呈现，不混入默认生物结果。界面先选对象类型，再显示适用筛选；动物的水层/群养不留在石材筛选中。石木沙要显示可供设计使用的尺寸/材质信息；物种图鉴条目与一个具体尺寸的设计素材不得混成相同实体。不得把尚未录入的分类做成有虚假数量的营销入口。

**手机**：搜索常显；“筛选”打开底部面板或整页抽屉，呈现已选数、应用、清空。关闭未应用筛选保留已生效条件；“应用”更新列表，计数宣告并把焦点移回筛选触发器。支持一列照片卡或紧凑行式，不在 390px 内硬塞三列小卡。滚动返回保留条件、排序、语言和位置。

**状态**：首次加载用少量定尺寸骨架，不编造卡片内容；条件更新保留旧结果并显示局部加载。零结果展示一句原因、可删除条件和“清空筛选”，不推荐违反用户硬条件的物种。加载失败保留条件与重试；不存在的合法分类显示真实空态。无照片条目用统一的紧凑文字卡/行式，图片缺失状态一次表达；不为每项保留一大片灰框、不用鱼形图标冒充品种影像。有照片与无照片混排也要对齐内容起点，必要时提供全列表的紧凑模式。

**验收**：不显示“正式图片/Photo”这类重复证明标签；有图就让照片说话。AI 物种图不进入主图和搜索结果。筛选仍满足既有 OR/AND、未知值处理和 URL 历史契约。筛选控件具可读标签与键盘状态；整张卡可进详情，但“加入方案”若作为独立操作必须用独立按钮，不能嵌套交互链接。

### 3.3 详情：先认识，再判断条件，最后查操作

**桌面文字线框**：`返回列表（保留上下文）` → `左约 58% 主照片/图集；右名称、学名、一句识别说明、加入方案` → `基础条件紧凑数据表` → `饲养环境与群体` → `喂食与布置` → `具体混养/风险` → `可展开共用养护指南`。照片区域本身已表达物种身份，不叠加“精选/易养”等徽章。基础条件只出现一次；已有重要提醒默认可见。

**手机**：名称与必要身份信息、主图、主要条件顺序连续；“加入方案”在身份区可见，也可采用不遮内容的底部操作区。长文按真实任务分节，避免多个折叠层互相嵌套。识别特征可展开，必要风险不能折叠到用户看不见。

**加入方案**：无当前方案时先选新建/已有方案，再确定数量；有方案可直接加入并允许撤销。仅有照片而无场景素材时，仍按实际数量创建带名称与虚线轮廓的占位实例，清单同步说明素材缺失。添加不等于适养通过；返回明确数量和后续检查结果，不给统一绿色“适合”。

**状态**：加载保留结构；条目不存在提供回库与搜索；部分字段缺失仅该字段待补充；整段无信息隐藏标题，不能留下空模块。无照片时压缩为身份区 + 一行缺图状态，不做英雄大灰框。图片失败显示可恢复的图片状态且保留文字资料。条件审核中仍可阅读，但涉及验证的字段不能被当成确定值。

**验收**：图集不裁掉关键识别部位，必要时可查看原图/完整适配。中英长名称、属级鉴定（例如 sp.）保持原义。图片替代文本描述实际可见个体，性别/品系不确定就不编写。重要群养、加盖、幼虾捕食等物种特有条件可见，符合现有资料边界。

### 3.4 开缸设计器：从选缸到配置，再看方案

**首版建议**：仅淡水，两套可改尺寸的长方体模板为“淡水水草社区缸”和“淡水砂木景观缸”（建议以 45×30×30cm 和 60×30×36cm 为设计测试基线；最终尺寸与配置须按技术、养护规则确认，不是已获批商品规格）。先做 2D/2.5D，提供正面与俯视两个同步视图。缸尺寸可用真实 cm；不做自由 3D 摄像机、模拟生长、真实光学、AI 自动造景或照片级渲染。两模板以构图与养护任务区分，不将混合地域素材称为“严格原生缸”。缸型扩展到异形缸前必须补齐几何与规则，不用矩形包围盒冒充有效水量。

**桌面文字线框**：`顶部：方案名称、保存状态、撤销/重做、保存/导出` → `左 220–240px：缸型 + 动物/水草/石木/底沙素材，搜索与少量适用筛选` | `中央自适应画布：正面/俯视、缩放、适配、选中对象` | `右 260–300px：选中对象属性 / 配置清单 / 条件检查`。在 1280px 以下把右栏改为可切换抽屉，保留画布可用宽度；不要为保留三栏把字缩小。主画布初始占工作区约 55–65%，实际以尺寸和测试决定。

**主要顺序**：选缸型与尺寸 → 选底沙并定厚度/分区（首版按技术方案限制作业） → 添石木、水草 → 添动物与数量 → 查看冲突与资料缺口 → 保存/导出。顺序是引导，不强迫每步完成才能返回。清单与画布共享同一对象 ID；列表改数量必须同步场景，删除后可撤销。

**素材与摆放**：拖入不是唯一入口，每项都有“添加”。添加后可用属性输入位置、旋转和允许范围内的尺寸；选中对象可键盘移动、按钮调整物理纵深、复制、删除并撤销。手机用点按素材→添加→点按位置→属性调整，支持方向步进和数值输入；手势拖动为加速手段。石木可按允许尺寸缩放；动物按固定成体尺寸展示，首版不设年龄档，不为美观任意放大；水草的成熟形态/出售株形需区别。不会正确缩放的素材不开放缩放控件。

**数量与比例**：动物每个个体对应 1 个场景实例，清单中 12 尾就显示 12 个实例；不能用 1 尾代表鱼群。本期不做抽样/代表显示；达到技术合同规定的场景对象上限时明确阻止新增，保留当前数量，并提示上限与处理方式，不能自动切成代表鱼群。水草的“一盆/一丛/一株”、底沙厚度、石木的具体尺寸都须有计量合同。画布有可开关标尺，正面与俯视遵循同一尺寸。未知真实尺寸的素材只能作为明确标注的示意，不能参与空间与数量判断。

**预览边界**：正面负责构图与层次；俯视负责底面积、分布与遮挡检查；两个视图共享 x/y/z 和朝向语义。2.5D 层叠不自动等于真实碰撞、水下成像或自由游动。动物水层位置为示意，不承诺静止于某个坐标。场景视觉效果与饲养适配结论分别呈现；配色好看不能导致适养通过。条件检查显示具体对象、问题、依据和可做的修正；资料不足与已知冲突分开，不能以一个“健康分数”盖过未知值。

**手机文字线框**：`顶部紧凑方案栏` → `可适配/可全屏的画布，正面/俯视切换` → `素材 / 清单 / 检查三个入口` → `底部可收起的面板`。单屏只展开一个面板，选中对象打开属性面板；关闭回到画布并保留选中。系统返回优先关闭当前弹层，再离开设计器；离开有未保存更改时提供保存/放弃/继续编辑。旋转屏幕不重置方案。

**状态**：空缸即真实起点，提供“添加底沙/添加素材”，不塞十个教学标注。素材库加载失败可继续编辑已缓存对象；缺场景素材、加载失败或已下架对象保留带名称与虚线轮廓的占位实例，位置、数量与清单一致，并提供重试/替换，不能静默删除或只留清单。不得以正式照片直接贴在场景冒充透明对象。完全未知身份的导入项进入待处理区，不参加检查，待用户完成映射再进入场景。保存中、已保存、保存失败、离线/未同步（若支持）必须精确；失败保留本地编辑并可重试/导出。超出边界、无效数值、缺资源版本须显示具体对象与修正入口。模板加载失败不覆盖当前方案。

**可访问性**：画布同步提供完整对象表/树，可读出名称、数量、位置和尺寸；在对象表选中能联动画布，也能独立完成编辑与删除。所有变换有数值控件，焦点与选中描边明显，选择不只靠色相。缩放和平移不能截获全部页面滚动或键盘导航。

**验收**：一条完整的桌面和手机路径都能“新建→添植物/硬景/动物→改数量/位置→检查→保存→重开”，并验证两个视图与清单一致。检查手机无拖拽路径、键盘路径、40 个对象主流程、200 个对象压力及300节点上限场景（具体预算由技术探针冻结）、边界/长名称、撤销恢复、未保存与保存失败。PNG 导出仅保留极简“设计示意”角标；方案版本、详细数量与缺素材说明放在随附清单/JSON。画布导出保留与实际方案一致的实例和必要占位，不用额外标签挤占构图。

### 3.5 后台编辑：让内容与素材可持续生产

**桌面文字线框**：`左：条目/分类/参数/素材入口` → `中：编辑表单（身份、适用类型参数、本地化、关联素材）` | `右：前台卡片/详情预览、校验问题` → `固定底栏：草稿、预览、校验并发布（维护者）`。密度高于前台，但字段分组清楚，不照搬消费端大卡片。分类和参数管理独立，不让编辑员在文本框中手写枚举值。

**编辑要求**：类型决定可用参数与单位，范围数据用 min/max，不用自由文案代替结构；未知与不适用明确区分。切分类若使已有字段失效，列出影响并确认迁移/清除，不能静默丢值。双语采用切页签或并排，缺失项集中定位；不因一语保存覆盖另一语。物种资料、可摆放素材、展示照片的关联在同页可见，但彼此身份独立。参数改动必须显示对已发布条目和现有方案检查的影响，版本行为由技术方案落实。

**素材管理**：缩略图、实际尺寸、视角、物种绑定、可用状态一屏可查；上传前检查类型/尺寸/透明通道等，上传后允许焦点裁切和 alt 编辑。发布前展示实际前台裁切和设计器缩放预览。缩略图漂亮不等于场景素材通过。

**手机**：后台优先桌面完整编辑；手机至少支持检索、预览、校验与小项修正。若首版不承诺手机复杂素材编辑，明确列为范围边界；基本表单不可横溢。数据表可在容器横滚，但名称与关键操作保持可发现；危险操作不只放悬浮菜单。

**状态**：空列表引导新建；表单加载失败可重试，已有未保存编辑不清空。字段错误就地提示并在顶部提供可点击错误清单；保存失败留表单。并发冲突展示谁/何时更新及差异，允许刷新副本或保存新草稿；不能最后写入者静默覆盖。无照片条目运行时可降级，但不能被当作有照片条目投入主视觉；正式候选素材完整性仍按 R1/R2 基线验收。上传失败、发布校验失败、预览失败分别有恢复动作。

**验收**：不懂 JSON 的编辑员可新增分类参数、填中英资料、绑定照片与场景素材、预览并提交；校验能阻止错误单位、反向范围和错物种绑定。后台状态是内容管理动作，前台不自动透出冗余“已发布”标签。

## 4. 素材交付契约与缺素材降级

使用自己拍摄或已有明确使用权的素材；AI 不冒充物种主图。

### 三类素材必须分开

| 类型 | 用途与最小交付 | 禁止混用 |
| --- | --- | --- |
| 真实物种/材料照片 | 图鉴主图与图集；原片、核对后的物种/品系标识、焦点、安全裁切、中英 alt、可追踪版本 | 不用 AI 生成图作识别依据 |
| 场景可用素材 | 设计器透明切图、矢量/程序化形状或受控 2.5D 资源；正面/俯视对应、尺寸、锚点、朝向、单位和可缩放范围 | 普通照片不是可摆放对象；不同鱼用通用剪影时必须标为示意，不能宣称真实外观 |
| 品牌与装饰 | 首页插画、纹理、小型图形；可使用 imagegen 辅助，检查最终视觉效果 | 不替代物种主图，不暗示 AI 缸景就是用户方案能精确生成的效果 |

素材记录最小字段建议：`asset_id`、`asset_type`、`entity_id`、`version`、`availability`、`file_variants`、`alt[locale]`、`focal_point`。场景素材另含真实 `width/height/depth` 与单位、`view`、`anchor`、`orientation`、透明边界、`scale_limits`；不适用项显式为空。最终 schema 与命名由数据/技术负责人统一，不能仅在设计文档中建立第二套事实。

建议照片源图长边至少 2000px，输出 480/960/1600px 等响应式版本；保留原片，不放大低清文件伪装高清。场景素材按实际最大显示尺寸提供适当分辨率，透明边缘须在浅底、深底和砂底上检验。AVIF/WebP 为可选派生格式，保留兼容版本；文件命名含稳定 ID 和版本/内容指纹。具体体积和加载预算先测真实素材再冻结，不只压到某个体积就牺牲识别细节。

**统一候选首发范围（待总方案批准）**：18 个生物条目 = 现有 10 个动物 + 2 个螺类 + 6 个水草；8 个可选择的造景材料目录条目，每项至少 1 个默认尺寸/材质配置（不是 8 大类各自扩展多 SKU）。具体命名与条目映射由数据方案冻结，不能把泛化类型名当成一种有统一尺寸的物体。两模板为“淡水水草社区缸 / 淡水砂木景观缸”，不宣称严格地域原生。

| 素材交付项 | 首发数量基线 | 通过与降级 |
| --- | --- | --- |
| 真实图鉴/材料照片 | R1 正式候选须齐全的 26 张独立主图：18 生物 + 8 材料实例；每张均核身份/材质 | 不能用同一张通用照片顶多个物种/材料。运行时缺图用紧凑缺图状态；缺图不算完成 R1。减少基线必须作为明确范围决策 |
| 可摆放场景资源 | R2 正式候选须齐全的 26 个可用对象定义：18 生物 + 8 材料实例；每个正面、俯视各一套可用表示，共 52 套视图表示 | 这是表示数量，不强制为 52 张位图：底沙可用程序化表现，但两视图和计量必须一致。运行时缺素材用带名称与虚线轮廓的占位实例保留数量；缺视图不算完成 R2。减少基线必须作为明确范围决策 |
| 模板封面 | 2 张，分别匹配实际可打开的两套模板 | 优先从实际场景导出；照片只有与实际配置/构图相符才可作对应封面。不相符摄影只能作独立参考，不能伪装为一键还原的模板效果。缺封面用实际简洁场景预览，不放无关美图 |
| 首页造景主图 | 1 张真实造景图，可与经核对的模板实景照片复用 | 没有对应模板时只作品牌摄影；不绑定“打开此模板”。缺失时启用色块/文字降级，同时记主视觉发布门槛未满足 |

动物场景首发按方案完整数量呈现：每个个体 1 实例，到对象上限阻止新增；代表显示或抽样模式仅可作为后续另行评审的功能。前台只计入已公开的真实条目/素材，不展示未来承诺数量。

**运行时降级**：照片缺失 → 紧凑文字资料；已知对象的场景资源缺失或已下架 → 每实例保留名称与虚线轮廓，继续保持位置、数量和清单一致；只有单视图 → 缺少视图采用同样占位，不宣称双视图完整支持；真实尺寸未知 → 明确示意并不参与空间判断；完全未知身份导入项 → 待处理区，不参与检查。运行时降级保证旧方案可恢复，不降低正式 R1 的 26 张照片、R2 的 26 套双视图素材门槛；若减少必须明确改范围。首页不得依赖尚不存在的摄影交付才能渲染；但主视觉缺失应记为视觉发布门槛未满足，不能以降级页面宣称最终美术已验收。

## 5. 设计到上线的阶段门

| 阶段 | 必须看到的交付 | 通过条件与责任 |
| --- | --- | --- |
| G0：需求与方向 | 本文 + 总产品/技术方案、明确首版边界与两方向对比 | 用户选定方向、范围与优先级；设计/技术列清仍待决项。未通过不实施 |
| G1：真实内容与视觉基线 | 真实照片候选、两模板素材清单、tokens、五页桌面/手机关键构图（本轮不制作） | 用户/设计负责人确认构图与密度；内容负责人核物种，素材负责人核照片和场景的可用性；缺图方案也审一遍 |
| G2：交互与数据合同 | 设计器两视图/数量原型、后台完整任务流、状态稿、字段/素材合同 | 技术证明同步、可访问操作、保存和版本可行；不可通过静态漂亮图替代 |
| G3：端到端实现 | 五页真实数据实现；中英、所有异常状态、手机与键盘路径 | 产品任务完成，数据不误导，未交付素材不伪装；功能 QA 与视觉 QA 分开签收 |
| G4：发布候选 | 真实服务器、生产资源策略、回归证据、升级前后截图与已知限制 | 通过下面的缓存/真实浏览器验收，再由用户对发布候选批准；不把本方案批准自动当发布批准 |

### 视觉与回归验收必须可复核

1. 用同一组真实内容核对 1440/1280/1024/390px 中英页面，补 320px 可访问回流检查；不是只截首屏。首页看主图、库看有图/缺图混合、详情看长名/缺字段、设计器看有对象/名称与虚线占位/错误、后台看真实校验/长文。
2. 每页检查图像主体、裁切、尺寸与比例、字重与对比、对齐、空白、重复标签；关键照片不可模糊、变形或错误绑定。若首版素材不够，承认交付未满，不用渐变和多层阴影填充。
3. 用实际任务演练和用户视觉选择签收；可采用“能否从照片辨认条目、三秒内找到主动作、无需说明完成手机添加与改数量”作为观察项，不把主观分数当功能证据。设计者提供参考构图与实现并排对照，记录偏差及接受理由。
4. 运行既有筛选、URL、历史返回、双语、未知值等回归，并增设计器/后台关键路径；本轮没有编写或运行这些新测试。完整截图出现拼接异常时对照 DOM 数量、实时视口与分段截图，不仅依赖全页截图下结论。
5. **缓存是独立发布门**：前次只在全新浏览器验收会漏掉用户旧标签页，现本地预览已有 `Cache-Control: no-store`。新一轮同时覆盖全新浏览器上下文、保留旧缓存与 localStorage 的已有配置、升级前已打开的旧标签页、普通刷新、前后退、深链接直达、切语、方案重开。验证 HTML/JS/CSS/JSON/媒体版本协调，旧页面恢复后不混载新旧 schema；生产不可只照搬开发 no-store 或假定硬刷新解决用户问题。技术负责制定内容指纹/资源发布/失效与兼容策略，QA 在实际目标服务器验证响应头和页面行为。用户实际旧路径也必须纳入验收。
6. 保存截图对应的 URL、语言、视口、发布版本、数据版本、浏览器与缓存场景。自动检查通过只是覆盖范围内的证据；设计负责人审核真实渲染，产品/数据负责人审核正确性，用户对关键视觉和任务流程签收。

## 7. 首版交互合同补充

「我的方案」放在设计器内，不加第三个顶级导航。动物无年龄档且按成体比例；前后调整直接改纵深，不能产生独立于俯视位置的视觉层序。底材首版最多两个覆盖缸底的矩形层，可调前/后厚度，任意形状分区留待后续。默认场景保留的未知项要集中在检查区展示，不给每尾动物贴多个状态标签。

R1先验收首页/水族库/详情/后台，设计器入口暂不公开；R2再验收设计器和模板。后台仅一名维护者角色，草稿→校验→预览→发布，不引入多级审核。实物照片、场景素材以及品牌图各自验收；图片降级可用不等于正式素材交付完成。技术和设计意见以本目录总稿为准，输入稿仅供追溯。
