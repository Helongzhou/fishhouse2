# Aquarium V0.3 开工基线 / Production baseline

更新：2026-11-05。本文是本轮接手后的范围与实施状态入口，优先于 V0.1 初稿。用户已授权多 agent 实施，并追加物种习性、自然随机行为、照片参考、水草分类及可扩展多语言国际化要求：英文母版/默认回退，简中为首批语言，首发语言尚未冻结。

## 产品与内容边界

定位：PC / Steam 单机、真 3D 淡水布景养成。先验证亲手开缸和停留观察，Unity URP 为目标实现环境。**本轮交付是数据、可执行 C# 行为/混养内核与 Unity 演示源码，尚不是经过编辑器验收的可试玩游戏。**

- 60 缸指长 60cm。教学内部尺寸暂定 60×30×36cm，毛水量 64.8L，有效水量设计值 54L；不是把“60 缸”换算成 60L。
- 一套三角模板，底砂、主石、辅石、三种植物、瀑布过滤、低光灯。沉木可选，附生植物可固定在石上，不要求买沉木才能继续。
- 首批入鱼使用 Ember Tetra（火焰灯），主养使用 Neon Tetra（霓虹灯），虾为 Red Cherry Shrimp（樱花虾）。白云金丝作为后续偏凉水路线参考，避免默认路线升到热带温度后持续不适。
- “闯缸”保留为分阶段养成概念；实际进度必须先完成**无鱼氮源挑战和稳定检测**，之后才是首批入鱼的适应观察。不能让鱼的死亡来证明水是否有毒。
- 熊猫鼠用于底栖习性开发夹具；虎皮鱼、神仙鱼、斗鱼的混养风险用于规则验证。它们不会因资料库有条目而自动进入默认 60cm 缸商店。
- 螺纳入资料、命名和资产类型；当前 Nerite 只是类群候选，具体物种尚未确认。螺的爬附生产内容属于后续，不暗中扩大本轮切片。

## 必须先成立的观察体验

1. 个体有稳定性格、独立可存档随机状态和短时记忆；行为通过需求和环境加权抽样。随机过程仍服从空间、食物和安全约束。
2. 突然开灯引起程度不同、时机不同的反应；短期反复惊扰增加压力，长期安全才可能习惯化。正常日出渐亮不等同突然闪灯。
3. 靠近前玻璃是玩家存在的游戏代理刺激；部分鱼可能期待食物，未得到食物后散开。不是所有鱼虾看到镜头都整齐列队。
4. 实际食物有落点、下沉与份量，进食必须到达并消耗食物，不能只加一个“正在吃”标记。
5. 熊猫鼠的探底、虾的贴面驻留与小型灯鱼的水体游动有可辨别差异。螺后续使用表面导航，不套用自由游泳。
6. 场景未来提供真实遮蔽、食物热点和局部水流。当前演示的角落掩体和虾贴底是占位，不能当作完整三维硬景寻路已验收。

## 植物的独立维度

`placement_tags` 描述位置；`light_requirement / co2_requirement` 描述养护；`growth_form / planting_method` 决定种植与修剪。三者不能互相推导。

- 水榕、铁皇冠：根茎需露出，可附石/木；根茎与根不同。
- 莫丝：绑附或成片，修剪控制体积；没有可套用的水榕式根茎字段。
- 椒草：根入底床，冠部避免深埋；换环境后的融叶不直接等同死亡。
- 附着是种法，不是固定高度；同种植物可有多个造景位置标签。
- “前景一定难、后景一定易、所有红草靠加铁、所有辣椒榕都难养”不能写成规则。以具体品种和实测光照/养分为准。

## 多语言国际化与来源

以 `data/localization/locales.json` 管理独立 locale 语言包，母版/注册默认/最终回退均为 `en`；启动依可用已保存选择→Steam映射→系统locale/地区父级→en解析，无匹配时默认英文（当前无Steam SDK，adapter该值为null）；保存用户语言选择，内部 ID 与显示文本分离。首批 `en` / `zh-CN` 各269键，`qps-ploc`只作QA；其余规划 locale 不等于已翻译或可发行。首发语言待冻结，所有玩家 UI、风险原因、操作建议、商品、图鉴、流程与 Steam 文案须覆盖被选为 `release_required` 的 locale，漏键或质量不过会阻塞该语言发布。字体、文化格式、复数、语序、伸缩、RTL及实际构建均有独立验收，见[多语言规范](多语言国际化与命名规范.md)。

生物英文使用已访问来源页的名称；植物页面没有单独英文俗名时保留页面学名；其他语言展示名和别名按 locale 维护，不新增 CSV 语言列。记录 `source_id`、来源原文名称、学名和别名。分类修订通过别名迁移，不改存档稳定 ID。

`sources/references.json` 保存核验页，`art/reference_manifest.json` 保存资产研究任务。这里是参考索引，不包含已授权照片素材或已经制作的模型。Seriously Fish 的照片/商业数据再利用规则见其 Reusing our content 页面；引用研究不等于照片获准当贴图或商店素材。制作使用独立模型和贴图，多来源比对，未经确认的图片不进入成品包。

原交接五篇 Cursor canvas 链接本次访问返回 403，尚未读到全文。因此本轮以用户粘贴的已定要点为已知依据；新数值属于本轮设计提案，不冒称来自原数值文档。

## 时间契约

行为与输入采用真实秒，固定步长由代码定义。生态日缩放独立，暂定 1 游戏日 = 8 分钟现实时间（1x），2x/4x只缩放日历模拟；**这是原型调参，不代表已验证最佳节奏**。旧数值草稿的 12 分钟和按小时随意叠算废止。

完整暂停停止两个时钟和业务命令，相机和 UI 可用。离线默认不推进、不伤鱼，直到经过主动离线养护设计；不默默加入退出也饿死的惩罚。

## 制作闸门

原型检查可用 `python3 tools/validate_config.py`；发布用 `--strict-release`，模拟/生态/兼容性仍为 pending 时必须失败，不能为得到绿色报告而删除待办。

完整 V0 必须达到：真实构建中完成一次布景→无鱼稳缸→分批入鱼→投喂/换水→保存重载，并由玩家实际观察验证物种差异与停留感。Steam 价格只能是后续商业假设，当前不能据一条内部切片认定上市内容已足够。
