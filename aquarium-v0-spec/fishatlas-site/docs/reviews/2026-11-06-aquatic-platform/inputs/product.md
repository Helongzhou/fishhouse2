# 产品需求评审输入

状态：**本轮建议，待用户进行需求与技术评审；不构成已批准的范围或实现授权。**

目标：让爱好者从一个可理解的淡水缸模板出发，选生物和造景、安排位置、查看正面与俯视效果，保存一份可继续修改的开缸方案。资料库继续服务查阅；设计器承接原计算器入口。后台让维护者独立管理分类、资料、素材、模板及规则。

## 1. 现状与本轮取舍

依据 `README.md`、`schemas/README.md` 及九份 `data/*.json`：现有10种为9鱼1虾，20条中英本地化、10条饲养档案、4条成对混养规则、2篇共用指南；没有螺、水草或正式物种照片。`tank_profiles` / `tank_plan_items` 为空。6种开启计算器字段，其中蜜丽丽（Honey Gourami）档案为 `partial`；另4种为 `unavailable`，不能把现存数值或页面预留描述为已运行算法。既有溶氧与水流独立，未知资料有明确表达。

建议采用「结构化方案 + 可编辑2D/2.5D场景 + 有边界的规则检查」。正面为主要展示，俯视用于安排纵深；两视图共享同一清单与坐标。自由3D成本高且不增加本轮饲养判断的可信度；AI成缸照片不能稳定对应数量与布局，均不进入首版。用户本次要求的是可评审方案，当前阶段仅产出文档。设计器将替代历史规划中的P1计算器入口；不把旧预留负荷字段直接变成公开算法。

首版两模板建议为**淡水水草社区缸、淡水砂木景观缸**。它们覆盖现有资料和新增植物，不对产地与强水流作额外承诺。水体、结构、环境、地域分开存储；「南美原生」「溪流」「海水」「水陆」不混成一个互斥枚举。模板入口可组合这些维度，首版只展示已完成且可使用的两种，不摆一排不能点击的未来模板。

| 范围 | 本轮建议范围 |
|---|---|
| 首版必需 | 两淡水模板；12种动物、6种植物、8个材料目录条目；缸体与水条件；清单与数量；双视图布置；规则状态；本地保存及JSON导入导出；中英；后台编辑与发布；适配与无障碍 |
| 后续候选 | 分享只读方案链接、账号/云同步、多设备恢复、更多淡水模板与内容、参考设备清单、南美风格与溪流内容包 |
| 后续独立评审 | 海水/半咸水及活石与珊瑚体系、水陆与陆地区域、严格原生地约束、自由3D、AI照片、UGC社区与交易、设备功率和生物负荷模型 |

阶段统一建议为：**R1基础库+CMS+UI，R2设计器，R3后续**。R1先交付完整资料/素材、受保护后台与资料库视觉升级；R2交付双视图、方案存储及分项检查。公开设计器的首发门槛为R1与R2都完成；不能把R1资料发布误报为设计器完成。FR-17～23主要由R1交付；FR-01～16主要由R2交付；FR-24～26两阶段都验收；FR-27～28属R3候选。

首版「本地方案」仅指访客方案存储。**后台须有受保护的维护者登录与持久化发布能力**，不能把访客无账号误解为公开写入后台。后台首版只设维护者一个角色，不引入组织、审批链或学术审稿。优先选择轻量受保护CMS；具体存储与部署由技术评审定案。

## 2. 参数与数据边界

所有字段用稳定ID与单位；中英文名称独立。字段状态与内容发布状态分开。后台严格区分 `unknown`（未知）、`not_applicable`（不适用）、`known_none`（已知没有）与数值0；不能把空数组同时充当这三种含义。数值未知用 `null` 并附状态，集合未知通过状态表达；迁移既有空集合时保持未知语义，不能补成0、通用值或「适配」。旧字段迁移保留语义，尤其不能从溶氧推断水流，不能从缸升数推断缸长。

| 对象 | 首版必须管理的内容 | 可未知或后续内容 |
|---|---|---|
| 缸体/方案 | 内部长宽高cm、水位cm、水体类型、全水结构、温度°C/pH/GH目标、整体水流选择、模板ID/版本、方案版本 | 硬景排水量可人工填L；未填就显示几何水量估计。底床平均厚度cm可选，计算明确扣除底床估计，不把该结果称实测净水量 |
| 鱼 | 身份、成体长度、温度/pH/GH范围、最小缸量/缸长及其已知状态、群体模式/数量、活动水层、溶氧/流速偏好、性情/捕食与混养提醒、场景比例与素材 | 生物负荷、设备功率、繁殖成功率均不计算；没有已知最小缸长时保留未知 |
| 虾、螺 | 共用水质、群体与体型；虾的成虾/幼虾风险，螺的壳体硬度需求、繁殖方式与必要提醒；建议数量语义 | 不把虾的群居当鱼的群游；不因「吃藻」推导无需投喂或必然清洁 |
| 水草 | 水质范围、沉水适用性、前/中/后景及附生/底栽/漂浮类型、建议光照档、CO₂需求档、成体高宽范围、种植单位、场景形态与变体 | 无灯具数据时不做PAR/瓦数推算；「丛/份」为编辑器单位，不换算为一定生物量或除氮能力 |
| 石/砂/木/底床 | 材料类型、展示名、适用水体、尺寸/体积或铺设厚度、摆放方式、已知水质影响、清理准备提醒、场景素材与包围盒 | 水质影响可为条件性/未知；不通过图像估计pH变化，不默认全部石材惰性 |
| 模板 | 四维条件、默认缸体/水条件、初始清单/布局、推荐候选、说明、检查版本 | 模板是可修改起点；示例布局不代表真实生长、寿命或购买数量保证，也不是有保证的安全配缸 |
| 规则 | 稳定ID、适用对象与条件、结论、严重度、原因、建议动作、两语言、启用状态/版本 | 仅运行已实现规则；性别、个体性情、成熟度等缺失条件须保留未知 |

动物数量是方案事实；动物图形只是位置示意。鱼按成体比例绘制，每一个体对应一个逻辑与渲染实例；可以成组选取/移动，但不能把多尾鱼缩成一张无数量对应的示意贴图。实际数量在清单与选中对象面板可见。鱼不会因拖到另一水层而改变物种习性。植物使用当前设定尺寸显示，提供未来成株轮廓开关；首版不模拟随时间生长。硬景数量与场景实例一一对应；底砂以覆盖区域/厚度表达，不按石块方式反复添加。

### 清单与渲染对齐约束

此处「目录/库存」指可选内容，不代表商家现货。目录有18种生物、8个材料目录条目，每项稳定ID；这8项是目录条目而非8个材料大类，同一素材的变体不增加目录条数。方案项目引用目录ID及其版本快照，数量与种植/铺设单位为事实；渲染实例引用唯一方案项目和实例ID。

* 鱼/虾/螺：`实例数 = 方案数量`。验收例：12尾霓虹灯、6只虾、2只螺，场景应有20个对应逻辑渲染实例；物体遮挡不改变实例数。
* 水草：一丛/份对应一个可编辑场景实例。3丛小水榕对应3实例，不能暗示是3片叶或固定株数；份内叶片不另计。
* 石/木：每件对应一个实例，复制一件必须增加方案数量，删除必须减少；同一件的正面和俯视投影只计1实例。
* 砂/底床：以一条区域项目记录覆盖范围、平均厚度和估计用量；区域正面/俯视投影是一份数据的两个视图，不把贴图重复数当采购数量。
* 所有已识别的已下架或缺素材对象仍保留项目与占位实例；未识别导入对象进入待处理清单，不能静默删除或计入已渲染。导出前可复核「项目总量/实例数/待处理项」，无需将这些调试数字常驻用户界面。

## 4. 规则结论与异常

首版仅输出分项检查与未评估清单，不给综合安全分、统一最大饲养条数或「生态负荷百分比」。方案摘要展示问题数量、未知数量和已检查项目覆盖数，最多用一句说明。不要在每个物体旁堆标签。

| 状态 | 触发与用户可见含义 | 例子与动作 |
|---|---|---|
| 冲突 | 有已知且明确不满足的约束；优先处理 | 温度无共同区间、海水对象放入淡水方案；定位并修改/移除。首版无海水对象，但导入仍校验 |
| 需调整 | 已知条件性风险或建议未满足 | 群养数低于已知下限、已知最小缸长不足、捕食幼虾提醒；显示具体数量/空间差额或条件 |
| 未知 | 数据、输入或规则覆盖不足，无法判断 | 12种动物共66对中没有显式关系的组合、尚未填GH、未知石材影响；指出缺什么 |
| 已检查项通过 | 某项已运行检查未发现问题 | 温度共同区间存在且目标落在其中；必须附检查项范围，不能升级为「整个方案安全」 |

有多个状态时同时保留，排序为冲突→需调整→未知→通过。没有冲突但有未知的方案可保存、导出，摘要仍展示未知。条件性混养不能被水质重合覆盖；水质范围重合也不能保证个体共处。没有溶氧实测/设备信息时只给需求核对，不能宣称满足溶氧。造景遮挡、通道及植物拥挤仅提供几何提示，不输出生态空间充足结论。

允许保存不完整方案。仅阻止数据损坏（无效尺寸、非法数量、损坏文件）、不支持的介质和不能恢复的写入操作，不用硬性阻止保存来逼用户接受建议。首版不做开缸周期、药量、固定换水/功率、混养安全保证或生命状态预测。

## 5. 主用户流与关键状态

1. 选模板或从资料详情加入 → 设置缸体及水条件 → 在目录加生物/材料 → 改数量与布置 → 双视图查看 → 打开检查并处理问题 → 自动保存 → 导出清单/图片/JSON。
2. 回到方案列表 → 恢复/复制 → 继续编辑；无本地记录显示两模板起点，不能落到空白画布无下一步。
3. 维护者登录 → 编辑草稿及素材 → 预览数据与模板 → 校验双语/关联/规则 → 发布一致版本；失败保留草稿，前台继续上一版本。

| 场景 | 必须呈现的恢复路径 |
|---|---|
| 首次进入、无素材或无搜索结果 | 模板起点、可辨识替代图、清除筛选；不伪造照片 |
| 改模板、清空、浏览器离开 | 当前内容已自动保存；破坏性清空确认，模板可另建 |
| 失联/配额不足/隐私模式 | 当前编辑保留；明确本地保存失败，提供立即导出 |

## 7. 验收与小规模试用

建议用5名爱好者做一次任务试用：3名刚入门或计划首次开缸，2名有一年以上经验；桌面3人、手机2人。每人完成同一任务：选择模板，设定60×30×36cm缸，添加指定生物/植物/木石，改数量，发现并处理一个群养问题，调整布局，导出后重新导入。另测有意放入资料未知的对象，确认不会把「无红色」理解为安全。

| 验收项 | 首版建议阈值 |
|---|---|
| 主任务可完成性 | 至少4/5人在无主持人代操作下15分钟内完成；5/5能找到保存方案或导出入口 |
| 规则理解 | 至少4/5能说明一个具体问题及调整动作；5/5回答「有未知，不能据此保证整体安全」 |
| 可恢复性 | 所有试用导出再导入后清单、数量、坐标、条件一致；刷新恢复零丢失；损坏导入不覆盖原方案 |
| 内容与版本 | 基线数量达标、本轮初始集关键双语100%、后续各语种独立发布且无兜底泄漏、零断引用；草稿不可见；发布失败不出现半批更新；回退可复现上一版本 |
