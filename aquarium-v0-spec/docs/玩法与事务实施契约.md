# 玩法与事务实施契约

2026-11-05。本批是可执行 C# 玩法领域与 Unity 灰模接线源码；控制台验证不证明 Unity 编辑器、视觉、可玩构建或 Steam 发行已通过。

## 输入与边界

权威商品、份数、强制路线和奖励来自 `data/items.csv / plants.csv / route.csv / economy.csv`，由配置层映射为 `GameplayCatalog(ItemDefinition[], PlantPlacementRule[], RouteRequirement[], starterGrantCoin, trialRewardCoin)`。玩法目录不依赖 Unity、显示名或 locale。根茎、附生方法与允许表面分别保留；当前三个默认植物只实现附生，未出售的椒草等不自动变成已支持内容。

初始1500；基础1110；首批火焰灯整份120/8尾；樱花虾180/6只；一次适应奖励450；霓虹灯260/8尾；正常路线最终280。预算保护按下一次奖励之前尚未拥有的必购批次数计算；已付未摆放计为拥有，确认时另验部署。重复买够数量之外的物品同样不能侵占路线储备。奖励后可支配余额只需保留尚未买的260主鱼。完成后取消教学预算保留。

## 公共接口

代码位于 `unity/Assets/_Game/Core/Gameplay/`，命名空间 `Aquarium.Core.Gameplay`，目标 C#7.3/netstandard2.1。

- `GameplaySession(GameplayCatalog, TankBounds)`；只读 `Paused / Filled / Stage / WalletCoin`。
- `Buy(transactionId, itemId)`、`Refund(transactionId, batchId)`、`Sell(transactionId, batchId)`。
- `Place(transactionId, LayoutPlacement)`：新ID放置，现有ID移动/yaw旋转；现有物件尺寸固定。
- `Remove(transactionId, placementId)`、`SetSubstrate(transactionId, SubstrateProfile)`、`Undo(transactionId)`、`Redo(transactionId)`。
- `ConfirmLayout(transactionId)`、`Fill(transactionId)`、`RefreshProgress(transactionId, EcologyEngine)`。
- `GetSubstrateHeight(x,z)`、`SuggestedBottomHeight(position,size,yaw)`、`CalculateEffectiveWaterLiters()`、`ReservedRequiredCoin()`、`LiveAnimalCount()`。
- `SetPaused(bool)`；`Capture()`；`static Restore(snapshot,catalog,tank)`。

命令返回 `CommandResult { Success, Code, Args[], BatchId, EntityIds[] }`。只有成功事务写幂等回执；同ID同负载重放原结果，同ID不同负载拒绝。失败不会改变钱包、物件、历史或回执。回执至多20000条，达到上限返回结构化失败；不静默丢弃旧ID。ID由调用方生成，存档保留。

动物购买按批次生成稳定实体ID；金币扣除和批次交付同时提交。回收整批移除全部实体，首次确认前全退按购买批次付款值结算；首次确认永久关闭全退。教学完成前保护最后一套必需品，避免半价出售造成教学软锁。已部署的固定硬景、底砂与设备本批不支持回收，植物和动物的整批回收仍受阶段与依赖约束。支撑仍有附生草时须先移草或退款草，不能留下悬空实例。

当前 ContentVersion 冻结价格：恢复时 `PaidCoin == 当前目录购价`，已售 `SaleCoin == min(PaidCoin, 当前目录回收价)`。现批不默默迁移历史调价；以后调价须显式版本迁移，退款结算仍读取已记录实际付款。

## 布景几何

尺寸、位置与底砂高均以米计；水平原点为缸中心，y=0为缸底。硬景和设备 `Position` 是盒中心，附生草 `Position` 是表面锚点，植物盒向上延伸。`Size` 是可信灰模/资产包围盒参数，UI不提供任意缩放。yaw绕y轴。

底砂四角高0.005至min(0.08,0.3×缸高)，角间最大差0.05m；双线性高度采样，不模拟连续沙粒。石盒底面落在其四角底砂最高处，允许4mm灰模支撑容差。石盒间使用XZ分离轴测试和垂直重叠检测；所有旋转角点必须在缸内。设备只验证边界，不参与石间碰撞；未声称全场景物理/网格导航已完成。

附生植物须有合法石/木支撑，锚点在宿主水平足迹内且靠近盒顶（15mm容差）。水榕与铁皇冠拒绝埋根茎；莫丝使用绑附表面规则。三种草均可附石，不强制买沉木。移动支撑同时变换附生草；底砂坡改变会重新安放石和附草。新布局整体验证成功后才提交。

干缸可放置/移动/旋转、改坡、撤回。首次确认后底砂、硬景与设备锁定；本批允许已部署植物移动/yaw旋转与改附着，保留尺寸和实例。湿缸不增加或撤下实例。每次几何编辑可撤销/重做，最多各32步；购买/退款/回收/确认/注水清除历史，避免经济事务后撤销复活库存。历史随存档保存且恢复时验证，确认后的历史不能修改固定物件。

水线为缸高−0.03m。有效水量=水线以下毛体积−四角均高底砂体积−浸没硬景盒体积，m³×1000转L；设备、植物不扣体积。它是灰模近似，不是任意真实石头体积。54L为默认设计参考；检查布景得54.216L，系统使用实际几何结果，不强制凑54L。

## 进度与跨域事务

`Editing → Confirmed → Filled → Cycling → CyclePassed → TrialObserving → MainUnlocked → Complete`。

`ConfirmLayout` 验证必需底砂、两石、三草、灯与过滤均已部署；`Fill`只执行一次。没有公开 `CompleteGate`。`RefreshProgress`读取真实 `EcologyEngine.Challenge` / `TrialObservation`，只有挑战/观察证据已通过且当前 `WaterIsStable` 才晋级；空缸双零或单纯过去若干日不触发挑战门。适应奖励前所有奖励前必购项须仍有效拥有，奖励ID与加币/过门同事务提交。

启动挑战、购买首批后的生态观察起动、当前水质入鱼保护、动物行为实例交付、食物氮桥接等由 `GameSession` 协调。领域 `Buy`不持有生态引擎；玩家入口必须经 `GameSession.Buy` 的当前水质与范围检查，不能直接绕过适配层调用领域库存。挑战/适应门的连续时间与质量阈值由生态模块统一维护，玩法不复制科学公式。生态参数仍为原型游戏调参。

Gameplay快照包含schema1、SaveId、钱包、阶段、注水/暂停、水线、布局、购买/退款/回收批次、幂等回执、已领奖励和几何历史。恢复先构造候选，校验数组/范围/完整性、实体ID、回执关联、阶段、布局、价格与钱包账本，再替换引用。钱包应等于初始与已领奖励−未退购买金额+出售所得。

完整的 World/Ecology/Gameplay 联合恢复、原子文件写入/备份与风险检查点由整合模块拥有。Gameplay的domain快照替换会同时撤销出售所得并恢复批次，不能把重试做成资产叠加；单机任意重写整个合法存档不属于密码学防作弊目标。本批不声称已实现长期排水重新布景、完整植物成长或 Unity 实测。
