## 免费养护与预算保护

基础饲料和换水均0金币；在没有持续收入循环的V0内，不能让玩家因养护开销而无法继续。免费不等于取消生态后果：过量投喂和不当操作的影响由待实施模拟器处理，不以收费代替后果。

`reserve_remaining_required_cost`要求：教学完成前，每笔可选购买后，钱包必须足以支付**下一次阶段奖励之前**所有未购买的强制项。计算时按实际账本扣掉已拥有并有效部署的强制配置，不能仅看当前余额够不够买本件。

当前路线在首个奖励前仅有90金币余量，因此140金币沉木不能抢占鱼虾预算；通过奖励后仍须为260金币主养套装留足资金。被拦截时，每个选定发行locale的UI均须说明“还需预留多少金币”，并让玩家继续完成教学或撤销购买。

## 交易、退款与重试事务

1. **购买**：检查范围状态、解锁门、预算保护、余额和套装份数；以交易ID记录商品ID、实际支付额、交付数量和库存变化。扣款和交付同时提交；重复命令不得再次交付。
2. **首次确认前退款**：`pre_first_confirm_refund_ratio=1`。按原购买批次的实际支付额全退，移除对应库存/摆放；不按后续改价计算。无购买记录、重复退款或已被退款批次不能再次领钱。
3. **确认后回收**：使用表中整份回收价，不能高于实际购价；库存、场景个体和钱包一起变化。回收价不足以保证路线恢复，因此必须与预算保护和免费检查点重试同时交付。
4. **阶段奖励**：初始1500与适应观察450均每存档一次。奖励ID写入领取账本，与加币和过门一致提交；重载、重复事件、恢复检查点不能重复领取。
5. **免费失败重试**：`restore_snapshot_transactionally`整体恢复检查点的场景、钱包、库存、生物、进度、购买批次和奖励账本。是替换快照，不是累加补偿；不能保留出售所得又恢复被出售物。
6. **检查点与损坏恢复**：进入风险阶段前建立可用检查点；尚无确认点则回到首次布景编辑并全额退款。事务原子写入、轮换备份、异常退出恢复与版本迁移需实际集成验收；当前只有政策和行为快照检查，不能标记完整存档已完成。

不增加“反复失败发金币”“回收免费补偿鱼”或可重复正奖励的收入漏洞。免费重试本身不发金币、不铸造可出售赠品；同一检查点重复恢复后的总资产与奖励账本必须相同。

## 实施验收

- 按`route.csv`跑通后：8尾火焰灯、8尾霓虹灯、6只虾，钱包280；基础配置与3草俱全。
- 购买套装时分别交付8/8/6个体，不能把120、260或180误解成每尾单价。
- 新档可选沉木被预算保护拦截；首次确认前撤销必买项能按原账本全额退款并重新布置。
- 基础养护连续调用不扣金币，但必须由模拟器正确处理食物、水量和生态影响。
- 重复奖励、重复退款、保存中断和连续免费重试均不会增加总资产或丢失已提交状态；这些是待接入游戏后的事务验收。
- 数据检查使用`python3 tools/validate_config.py`；普通通过不替代UI、场景和存档实测，`--strict-release`当前仍有14项模拟/生态/兼容性阻塞。

## Steam零售价

**Steam售价、区域价和折扣尚未决定。** 它们是后续商业假设，需在可玩闭环、视觉质量、内容量及外部试玩反馈成立后单独评估。当前没有已批准的人民币/美元定价或首发折扣；游戏内金币也不与现实货币换算。
