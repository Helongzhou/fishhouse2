# 生态模拟实施契约

2026-11-05。状态：纯 C# 内核已实跑；Unity 编辑器、Play、真实构建及生物学标定未验收。`tanks.simulation_ready=false`、模型与来源审核 pending 保留。本实现是可标定的游戏原型，不是现实养鱼剂量、安全浓度或硝化周期建议。

## 单位与边界

所有氮质量以 **mg-N** 记录；界面 TAN、亚硝酸盐和硝酸盐统一显示 **mg-N/L**，不得直接标成 NH₃、NO₂ 或 NO₃ 化合物质量。默认有效水量 54 L；`EcologyParameters.VolumeLiters` 接受布局估算水量（1–100000 L），不将 60 cm 缸等同 60 L。单次换水保持相同有效水量：先排出，再补回等量新水。

内核当前没有氧、碱度、pH、温度、游离氨比例、藻、生物体重、生长、疾病、繁殖、死亡或离线推进。TAN/亚硝酸盐过门阈值是游戏保守指示，不能当作特定物种实际毒性证明。植物摄取仅为可选恒定速率夹具，默认 0，未与实际植物数量、光照或 CO₂ 耦合。

## 状态与守恒

`Aquarium.Core.Ecology` 的 `NitrogenPool` / `NitrogenState` 分为：

| 库 | 含义 | 自动去向 |
|---|---|---|
| Food / FoodMgN | 场景中仍可被摄取的固体投喂份量 | 由真实摄食/移除事件转移 |
| Organic / OrganicMgN | 已成为残留的可矿化有机氮，按混匀悬浮/溶解部分建模 | TAN |
| Living / LivingMgN | **摄食后的可代谢氮储备**，不是动物身体重量 | TAN |
| Tan / TanMgN | 总氨氮 | 亚硝酸盐氮 |
| Nitrite / NitriteMgN | 亚硝酸盐氮 | 硝酸盐氮 |
| Nitrate / NitrateMgN | 硝酸盐氮 | 可选植物摄取 |
| Plant / PlantMgN | 被摄取并留在植物库的氮 | 显式修剪移除才出系统 |

`LivingReserveLedger` 独立记录每个真实摄食实体的储备氮；重复摄食累加，生态 Living 代谢后通过 `Reconcile(actualLivingMgN)` 将各实体储备同比例缩放。出售实体时 `Remove(entityId)` 返回需调用生态 `RemoveNitrogen(Living,...)` 的出缸质量；未摄食实体返回 0。快照为 `LivingReserveSnapshot`，恢复须核对总额与生态 Living 相等，外层再验证所有归属 ID 都仍在缸中。这是储备的归属分账，不新增或重跑第二套代谢。

每次转化都先从来源库扣除相同质量，再加入目标库。总质量满足 `Σ各库 = 累计输入 − 累计输出`。投喂通过 `AddNitrogen(Food, mgN, sourceId)` 计入外源；摄食通过 `TransferNitrogen(Food, Living, mgN, sourceId)`，过期或容量淘汰通过 `Food→Organic`。没有随机生成“鱼粪氮”的过程。需要输入初始植物氮时，必须作为显式外源记录。

`ChangeWater(liters, incoming)` 按排出比例扣除 Organic、TAN、Nitrite、Nitrate，再按新水浓度×升数计入各库。Food 固体份量、Living 储备及 Plant 不随换水自动排出；吸走固体、移出生物/修剪等必须调用显式移除。新水不是默认零氮：`WaterComposition` 的四个浓度字段均为 mg-N/L。

`NitrogenAudit` 长期保留各库外源输入/输出、7×7 内部累计转移矩阵和总输入/输出。`EcologySnapshot.RecentLedger` 默认仅保留最近 256 条、可配置 1–4096 条明细；含序号、生态日、操作、来源/目标库、质量、sourceId。历史明细淘汰不丢累计质量账。调用者使用稳定的食物 ID 和业务命令 ID；长期逐笔来源取证如有需要应另写追加日志，不扩大游戏存档缓存。

## 时钟和可标定参数

内核只接受 `AdvanceGameDays(double)`，不自行读取墙钟，固定化学步长默认 1/1440 游戏日（1 生态分钟）。小于步长的余量进入快照，恢复后连续。单次接受 0–365 日；累计支持 0–1000000 日。场景外层采用 1 游戏日=480 现实秒，1x/2x/4x 仅改变送给生态内核的游戏日数量。相同生态时长和相同业务命令序列产生相同结果。

| 参数 | 默认 | 单位/含义 |
|---|---:|---|
| OrganicMineralizationPerDay | 0.65 | 1/游戏日，一阶矿化 |
| LivingMetabolismPerDay | 0.35 | 1/游戏日，摄食储备一阶代谢 |
| InitialTanCapacityMgNPerDay / InitialNitriteCapacityMgNPerDay | 各 1.5 | mg-N/游戏日 |
| MaximumCapacityMgNPerDay | 54 | 每级最大 mg-N/游戏日 |
| CapacityGainPerProcessedMgN | 0.6 | 每处理 1 mg-N 增加的 mg-N/游戏日能力 |
| CapacityDecayPerDay | 0.02 | 1/游戏日 |
| PlantUptakeMgNPerDay | 0 | mg-N/游戏日 |

每步有机矿化/储备代谢为 `来源量×(1−exp(−速率×dt))`。开滤时两级硝化各不超过当前来源量及该级能力×dt；本步产生的亚硝酸盐可在同一步被下一级处理。菌群能力按实际处理量增长，并按生态日衰减，上限截断。停滤时两级处理为 0，能力继续衰减；没有把过滤设计点直接换成硝化速率。以上参数尚未经过现实数据或玩家节奏标定。

`AquariumWorld` 的游动、反应、食物下沉/35 秒存在期和 Hunger 继续使用真实秒。Hunger 是觅食动机，不驱动氮生成、身体损失或死亡；空腹且无摄食储备不会凭空产生氮。鱼体氮库和饥饿伤害模型尚未建立。完整暂停由 GameSession 同时阻止世界/生态推进和业务命令；`SetEcologyRate(0)` 本身仅停原世界的生态日。干缸时也由外层阻止生态推进。退出不推进任何时钟。

## 无鱼挑战与首批适应

`BeginFishlessChallenge(int liveAnimalCount)` 必须由拥有真实个体列表的 GameSession 提供数量 0，同时内核检查 Food、Organic、Living、TAN、亚硝酸盐均近零（每库≤1e-8 mg-N）且开滤。开始操作原子加入非零 TAN，默认 `0.5 mg-N/L×实际有效水量`，54 L 时为 27 mg-N；空缸双零不会启动或通过挑战。

挑战依次处于 `NotStarted / Processing / Stabilizing / Passed / Invalidated`。两级实际氧化均达到剂量的 90%，并且开滤、TAN≤0.05 mg-N/L、亚硝酸盐≤0.05 mg-N/L，才开始连续 24 游戏小时稳定窗。按完整化学步两端安全计时；不安全或停滤将窗口清零。剂量、处理比例、两个阈值及窗口均来自可配置参数。

活动挑战中任何额外外源输入、手动库转移、手动移除或换水都会置为 Invalidated，不能稀释/清除氮获得通行。无效挑战不会自行恢复；须处理残留后显式重新挑战。可用完整换水排净水中残留后重启，也可等待剩余氮被正常处理后重启；挑战剂量仍重新入账，不能因一次失效永久卡死。Food 固体须先真实过期/摄食或显式移除。过关后保留历史证据，不因合法投喂撤销。后续入鱼仍应检查当前 `WaterIsStable`。

`BeginTrialObservation(int liveAnimalCount)` 只在挑战通过且真实个体数>0时启动，使用独立 `TrialObservationState` 连续水质稳定窗，默认同样 24 游戏小时。试养窗遇不安全/停滤归零，换水也重新计时；不靠动物死亡证明循环。Passed 是已完成的历史证据，主鱼购买/解锁还需 GameSession 检查当前水质、物种适配、实际库存与其他玩法条件。该窗口不宣称已模拟完整动物健康或生理适应。实际个体在观察中被移除/换批时，外层必须阻止旧批次证据被复用。

## 公共接口

源码：`unity/Assets/_Game/Core/Ecology/EcologyModels.cs`、`EcologyEngine.cs`。主要调用：

```csharp
var ecology = new EcologyEngine(new EcologyParameters { VolumeLiters = effectiveLiters });
ecology.AddNitrogen(NitrogenPool.Food, totalMgN, foodId);
ecology.TransferNitrogen(NitrogenPool.Food, NitrogenPool.Living, eatenMgN, foodId);
ecology.TransferNitrogen(NitrogenPool.Food, NitrogenPool.Organic, expiredMgN, foodId);
ecology.RemoveNitrogen(NitrogenPool.Plant, trimmedMgN, commandId);
ecology.ChangeWater(liters, new WaterComposition { NitrateMgNPerLiter = sourceWaterNitrate });
ecology.SetFilterEnabled(false);
ecology.AdvanceGameDays(realSeconds * calendarRate / 480.0);
EcologySnapshot saved = ecology.Capture();
EcologyEngine resumed = EcologyEngine.Restore(saved);
```

`State / Audit / Parameters / Challenge / TrialObservation` 返回独立副本；`Capture` 深复制数组及近期账本。参数在构造时冻结。命令在改动前校验有限数、非负、来源 ID、可用质量和换水范围；被拒命令不会改动 live 状态或把挑战误作失效。业务跨系统原子性由 GameSession 在候选副本上执行后统一提交。

`AquariumWorld.Feed(Vec3,int)` 现在返回原有刺激 ID（long），既有调用可以忽略返回值；行为快照 schema 2 未变。

```csharp
public event Action<long, string, int> FoodConsumed; // sourceId, entityId, portions
public event Action<long, int, string> FoodRemoved; // sourceId, remainingPortions, reason
```

`FoodConsumed` 在实际抵达并即将消费时同步发出；`FoodRemoved` 在自然过期/64 事件容量淘汰时发出，reason 分别为 `expired`、`capacity_evicted`。完全吃光不会再发残留移除事件。事件在原世界变更前通知，订阅者须在候选 World/Ecology 上记账；订阅者异常时丢弃整个候选，不能把事件直接写入另一份 live 生态对象。重载后需重新订阅。

快照恢复会验证时钟、范围、各库累计输入/输出/转移一致性、总守恒、近期账本连续序号和累计上界、挑战非零剂量、实际两级处理量及窗口不得超出经过时长。用于拒绝损坏或明显矛盾的数据；本地存档可被整体重写，本原型不提供密码学防作弊保证。
