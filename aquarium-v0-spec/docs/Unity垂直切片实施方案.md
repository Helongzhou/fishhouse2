# Unity URP 垂直切片实施方案

版本：V0.4 国际化修订版；更新：2026-11-05。范围与任务状态以 [开工基线与任务看板](开工基线与任务看板.md) 为准，源码导入及操作见 [unity/README](../unity/README.md)。旧稿已原样保留为 [整合前快照](legacy/Unity垂直切片实施方案-pre-integration.md)。

## 当前交付与目标

目标环境为 Unity URP，验证 60cm 淡水缸的开缸布景与停留观察。60 缸指长度，教学内部尺寸暂定 60×30×36cm，毛水量 64.8L，有效水量设计值 54L。

**当前交付是纯 C# 行为/混养内核、类型化数据和占位 3D 演示源码。没有 Unity 编辑器编译、Play 或独立播放器验证，尚不是可试玩的完整垂直切片。**

完整 V0 的目标路线为：三角布景 → 注水 → 无鱼氮源挑战与稳定检测 → 首批入鱼适应观察 → 主养鱼 → 投喂/换水 → 保存重载。鱼的死亡不作为证明水质合格的工具。默认路线的首批鱼为 Ember Tetra，主养鱼为 Neon Tetra，虾为 Red Cherry Shrimp；熊猫鼠属于底栖行为开发夹具。

## 时间、行为与存档契约

- 行为固定步长为 **1/30 真实秒（30Hz）**；相机、感知、受惊恢复、食物沉降和当前饥饿逻辑使用真实秒。
- **1 生态日 = 480 真实秒（8 分钟，1x）**。2x/4x 只改变独立生态钟，不能把鱼虾动作或反应直接乘速。当前生态钟尚未连接水质/生长模型，此节奏仍需试玩调参。
- 完整暂停停止两个时钟及投喂、灯光等业务刺激，相机与 UI 保持可用。
- **默认无离线推进、无退出后饿死惩罚**。当前读取快照恢复原时刻，不读取 UTC 差额补算。
- Utility 权重经扰动后随机抽样，结合最短动作时长、当前动作迟滞、强刺激中断；个体各有独立 RNG 与短时记忆。无同种伙伴时不选择群游。
- 灯光突变的反应存在个体差异和延迟。8 秒内连续开关累积短期压力；连续安全亮灯经过安静窗口及稳定期后才缓慢增加习惯化，上限 0.35。压力、习惯化及相关计时均保存。
- 玻璃接近只是玩家存在的游戏代理。部分鱼可能期待食物，记忆消退后散开；贴底虾不把相机当追逐目标。
- 食物有位置、沉降和份量，到达后才摄食。熊猫鼠有到位停顿探底，虾有贴底驻留；目前虾没有沿复杂石木表面的三维导航，也没有实际藻量消耗。
- 行为快照为 **schema 2**，保存位置、速度、动作、计时、个体 RNG、压力及未结束刺激。演示文件名为 `aquarium-behaviour-demo-v2.json`，旧 v1 不静默加载。
- 演示使用临时文件替换并保留一个 `.bak`；完整三备份轮转、自动回退、跨版本迁移、交易账本和 Steam 云存档仍待实施。

演示的 10 条小型中层鱼 + 6 条熊猫鼠 + 4 只虾是行为压力夹具，不能作为现实密度、经济路线或默认商店投放依据。虎皮、神仙和雄斗鱼仅有隔离配置；其咬鳍、缓流偏好与领地动作尚未实现。

## 多语言资源与资产

国际化以 `data/localization/locales.json` 注册表为入口，语言包独立存于 `data/localization/<code>.json`，生成同一注册表与 `Resources/Localization/<code>.json`。共享文本采用key→text，Unity envelope仍为 `{"language":"en","entries":[{"key":"...","value":"..."}]}`。新增locale只增加注册项和资源，不新增鱼虾螺草CSV语言列；英文规范名保留来源，其余展示名/别名按locale维护。

英文为母版、注册默认和最终回退；启动按可用保存选择→Steam显式映射→系统locale/地区父级→en，无匹配时才默认英文。当前无Steam SDK，adapter的Steam值为null，纯C#解析不代表SDK接入；en根节点fallback为空，其他locale显式指向回退且不能成环。`LoadedLocales`与`SupportedLocales`分开；正式选择只接受ready或启用的QA，draft经开发接口预览，planned不加载。`qps-ploc`检验扩展文本/硬编码，不能算发行语言；首批en/zh-CN各192键，首发语言清单仍待冻结。

本轮已复验12项国际化工具场景与49项运行时/行为检查，结果见实施记录；真实字体和排版仍须实际构建验收。`T`是开发切换入口，正式语言设置和PlayerPrefs重启保留仍需Unity实测；各语言文化数字/复数/语序、字体、长文本、错误反馈都需覆盖。仅声明direction不证明RTL支持，必须实际渲染与混排测试，详见[多语言国际化规范](多语言国际化与命名规范.md)。

鱼虾螺草参考来自研究索引，当前没有已授权照片素材或正式3D模型；研究引用不能当作图片已获成品使用授权。语言资源与来源资料、资产制作状态独立。

## 已完成的验证

以下为本轮多语言改造前已运行的检查记录；新增国际化结果见[实施状态与验证记录](实施状态与验证记录.md)，不得据此宣布新增locale或RTL通过。

纯 C# 核心以 C# 7.3 / .NET Standard 2.1 编译，0 警告、0 错误；运行时国际化与行为检查 **49 项通过**。验证覆盖：

- 180 秒行为轨迹中的边界、游层、动作多样性、摄食、鼠鱼探底和虾驻留。
- RNG 与 JSON 快照连续性、schema 拒绝、生态倍率和真实行为秒隔离。
- 8 个固定种子的快闪/稳定亮灯对照、有限习惯化和灯光记忆重载。
- 无同种时禁止群游、虾不追玻璃代理、误判投喂消退。
- NaN/Infinity 输入和腐损快照拒绝，以及共享英/简中 catalog 的实际读取与格式契约。

这些是无画面逻辑检查，不替代动作自然度、美术可看性、Unity API 兼容性或目标机性能验收。混养模块有自己的独立检查，不能因此认定商店和行为演示已经完成混养接入。

## 下一步实施顺序

1. 在有 Unity 的环境导入源码并进入 Play，验证相机距离、灯光反应、聚集/散开和物种差异；记录编译、输入和画面问题。
2. 完成一个代表物种和一套底栖动作的模型/动画小样，接入真实硬景碰撞、遮蔽和表面导航，检查是否值得停留观察。
3. 接 CSV adapter 与 Compatibility evaluator adapter，让稳定 ID、实际配置、商店检查及按locale本地化的原因/修复反馈形成同一条链。
4. 实施底砂/硬景/植物摆放、撤销和注水；按植物种法分别处理根茎、冠部和附着，不由前中后景标签推导养护难度。
5. 用氮质量守恒、可标定菌群和无鱼氮源挑战建立水质曲线，再接过滤、灯光、换水、进度门与经济恢复机制。
6. 完成全量存档、免费重试、目标机性能和所有选定发行locale逐屏验收后，再接 Steam 并生成可验收构建。

进入完整 V0 验收的条件是：真实构建完成一次布景 → 无鱼稳缸 → 分批入鱼 → 投喂/换水 → 保存重载，并由玩家观察验证物种差异与停留感。原型检查通过不等于发布检查通过；`--strict-release` 必须保留尚未完成系统的阻塞结果。
